# NorthStarCpp Renderer Provider Parity — Phase 1

Date: 2026-11-15
Scope: D3D11, D3D12 and Vulkan engine.render providers
Base Render ABI: **5, unchanged**
Build: `build/provider-parity-qa-20261115` (isolated QA, not production dist)

## Objective

Make API providers interchangeable at the *required-feature contract* level, then converge their actual GPU implementations. Base ABI compatibility by itself does not establish renderer feature equivalence, pixel correctness or performance parity.

## Completed in this phase

### Vulkan native depth rendering

Added a native Vulkan D32_SFLOAT or D24_UNORM_S8_UINT depth image, memory and view, dynamic-rendering depth attachment, pipeline depth-test/write (`VK_COMPARE_OP_LESS`) and explicit depth access transitions in the common Render Graph Vulkan Sync2 executor. Depth resources are recreated with the swapchain and released safely.

A new hardware readback mode (`verify_pixels=4`) checks that a closer green triangle occludes a farther red triangle in **both drawing orders**. Hardware Vulkan smoke and validation/stress tests passed.

### Vulkan PBR materials ABI v1

Published `NorthStarRenderMaterialsApi` v1 through `northstar_module_query` and the direct exported query. Implemented:
- strict bounded/copying material vertex + RGBA texture uploads;
- albedo sRGB, normal, roughness, metallic and emissive texture slots, neutral fallbacks;
- native `VkImage`/staging/copy, `VkImageView`, sampler and descriptor sets;
- coherent GPU material vertices, per-batch draws with real depth;
- GGX-style direct lighting with an unlit variant;
- source-byte-verified texture cache and conservative queue synchronization;
- `verify_pixels=2` two-color texture UV GPU readback.

Shaders are GLSL `material.vert` and `material.frag`; embedded SPIR-V is regenerated by `tools/generate_vulkan_material_spirv.py` using the Vulkan SDK's `glslc`. Changes to GPU resources have dedicated creation/destruction routines in `renderer_materials.cpp` and remain private to Vulkan.

**Important:** this is an initial native GPU PBR path; it is NOT the full D3D12 deferred material pipeline. A full Material Graph v2 compiler, GPU skinning and several other interfaces are absent in Vulkan.

### Vulkan dynamic lights ABI

Published `NorthStarRenderLightsApi` v1. Up to 256 dynamic point/spot sources are validated, copied and uploaded to a native uniform buffer; the GLSL PBR shader evaluates radius/spot attenuation and GGX shading. Invalid light inputs fail. GPU readback mode (`verify_pixels=5`) tests a lit material under a strong point source.

The cross-provider `render_provider_device_probe.cpp` additionally reports `lights_api_available` and `light_gpu_readback` independently of API negotiation. Vulkan lighting readback passed on hardware. D3D12's light API was discovered, but this specific new readback test is intentionally scoped to Vulkan; do not infer that the D3D12 scene-light parity test was run here.

### Project-required features

Added `render_feature_requirements.hpp` with 20 canonical named features and a shared validator.

The project manifest may contain:

```json
{
  "providers": {"engine.render": "d3d12"},
  "required_renderer_features": [
    "depth", "textured_materials", "material_graph", "hdr", "bloom"
  ]
}
```

This snippet illustrates the optional new fields; the complete existing manifest retains its other metadata.

The Catalog validates, atomically persists, reloads and duplicates requirements. The Qt Project Browser settings include a **Choose Mandatory Features** dialog, and the project launch validates both explicitly chosen and Automatic providers against requirements. Missing and unreported features are not considered supported. Automatic chooses a compatible backend, preferring D3D12, or refuses launch.

The editor child receives its own `NORTHSTARCPP_RENDER_REQUIRED_FEATURES` environment. Runtime Viewport rechecks exported extensions and feature declarations **before creating the GPU renderer**, including when launched without the Project Browser. The existing D3D12 → D3D11 automatic fallback cannot circumvent mandatory features.

This prelaunch validation checks module contracts and advertised features; it does not replace runtime per-GPU acceptance testing.

## Near-term priorities

1. **P0** Finish shared material IR and Vulkan Material Graph v2. Portable node IR must generate correct HLSL and SPIR-V while preserving material semantics (alpha mode, roughness/metallic/normal maps, asynchronous variants).
2. **P0** Complete common resource/scene contracts: GPU skinning, character meshes, world-surface BCn, dynamic lights and GPU timing on all backends.
3. **P1** Backport the D3D12 G-buffer/deferred lighting and shadow passes to Vulkan and D3D11 using Render Graph resource declarations; do not duplicate shader algorithms needlessly.
4. **P1** Implement shared HDR, histogram exposure, multiresolution bloom, color grading and tonemap passes and backend execution.
5. **P1** Add deterministic cross-backend GPU render targets/screenshots and pixel-difference thresholds; Night City stress and p50/p95/p99 GPU times across at least 1000 valid frames.
6. **P2** Expand Vulkan material performance from per-texture queue waits to batched staged transfers, descriptor reuse, coherent memory budget reporting, and crash-safe cache invalidation.
