# Script-first gameplay migration — NorthStarCpp

Copyright (C) 2026 Kayla's Systems — Kayla Verner.

## Ownership contract

Game-specific behavior belongs to a **project** (`scripts/main.js`, scene-attached
scripts under `scripts/`). The native engine owns general-purpose services:
ECS, scene serialization, physics simulation, collision queries, camera,
input sampling, rendering, asset streaming, logging and audio playback.
The engine must never select target names, weapon rules, player keybindings,
health thresholds, victory conditions or NPC missions for new projects.

## New source project execution path

When the project has `scripts/main.js` or any Scene V3 script component:

1. Player creates the ordinary PhysicsScene and provider-neutral ECS/scene services.
2. If the project requests FPS/explore presentation, the engine creates a
   first-person CameraDirector, **not** a native FpsArena gameplay instance.
3. Project JavaScript receives lifecycle events, input snapshots, scene queries,
   camera controls, collision sweeps, static object manipulation, player movement
   and basic game session/UI operations through allowlisted `engine.*` methods.
4. Gameplay script maps keyboard/controller inputs to movement, firing, pause,
   restart, interactions and game-specific state.
5. The renderer consumes scene/physics/camera snapshots. Script-authored color
   overrides are applied to an ephemeral render snapshot, not scene authoring data.
6. Hot reload re-evaluates project scripts into a fresh V8 context; failure
   preserves the previous runtime.
7. Exporting a project with scripts requires a selected compatible V8 provider.
   Assets and scripts are packaged together; V8's native code is not embedded
   into game scripts.

Scene V3 script components still run via the existing per-entity
`entity.start`, `entity.update` and `entity.stop` hooks. New gameplay
uses the already introduced versioned scripting ABI 2, never a legacy SDK.

## Available initial engine API methods

| API | Behavior |
| --- | --- |
| `engine.input.isDown(key)` | Read provider key status |
| `engine.input.mouseDown(button)` | Read mouse buttons |
| `engine.input.pointerDelta()` | Read relative pointer movement |
| `engine.input.gamepad(index)` | Read a neutral controller snapshot |
| `engine.player.move(x,z)` | Submit world-relative, bounded movement for this frame |
| `engine.player.jump()` | Jump through selected physics provider |
| `engine.player.eye()` | Read physical player eye position |
| `engine.player.setEyeHeight(height)` | Set camera gameplay eye offset |
| `engine.camera.setAngles(yaw,pitch)` | Set first-person camera direction |
| `engine.camera.angles()` | Read direction |
| `engine.camera.shake(amplitude,seconds)` | Native camera shake |
| `engine.camera.setZoom(amount)` | Camera FOV interpolation |
| `engine.physics.sweepSphere(...)` | Provider-neutral sphere query |
| `engine.physics.applyImpulse(index,x,y,z)` | Dynamic body impulse |
| `engine.scene.objects(start,count)` | Paged scene object metadata |
| `engine.scene.moveStatic(index,x,y,z)` | Update a static physics body |
| `engine.scene.setColor(index,rgb)` | Script-controlled visual color |
| `engine.ui.setTitle(text)` | Host window title, presentation only |
| `engine.session.pause(boolean)` | Pause world simulation |
| `engine.session.restart()` | Defer restart until JS callback returns |
| `engine.session.quit()` | Request normal window close |
| `engine.audio.play("audio/file.wav")` | Audio through mounted project assets |

All operations validate argument sizes and/or bounds. These APIs do not expose
native pointers, raw memory, network access or arbitrary filesystem paths.
The physics provider remains authoritative for collisions and dynamic bodies.

## Migrated projects

**Projects/NorthStarFirstPersonPlatform/scripts/main.js**
- Project-owned WASD/arrow-like movement, mouse/controller look, jump,
  physics impulse interaction, pause and exit.
- No native arena health/weapon/target code is activated.

**Projects/NorthStarFPSArena/scripts/main.js**
- Project-owned target detection, moving target animations, weapon settings,
  ammunition, reload timing, recoil trigger, hazard health, hit colors,
  win/lose/restart and pause.
- Generated by `tools/generate_fps_arena.py` using
  `tools/templates/northstar_fps_arena.js`.

**Project Manager sandbox/physics templates**
- New game templates include `scripts/main.js` by default and declare
  a first-person presentation mode with V8 scripting in their manifests.
- Project-specific titles are injected with JSON-safe quoting; no game name
  is hardwired into the native Player.

## Compatibility boundary and unfinished items

**This is a migration stage, not a claim that all C++ gameplay code has
been physically removed from the repository.**

- `engine/northstarcpp/modules/host/fps_game.cpp` and its old UI
  integration remain for projects with no scripts and existing native smoke
  tests. They are bypassed for script-enabled game projects.
- The old native FPS HUD is not yet mapped to a provider-neutral scripted
  HUD widget API. Scripted projects currently use the window-title status.
- No end-to-end native V8 runtime test has passed because
  `NORTHSTARCPP_V8_ROOT` is not configured.
- A full Player/Editor link, DLL replacement, and exported-game run remain
  unverified. Syntax checks and JS simulation tests do not replace them.
- Full removal of legacy FpsArena requires migrating remaining native
  smoke cases and separating compatibility HUD rendering.
- Scripted ECS mutations currently expose a bounded subset of components;
  arbitrary component schema reflection, state-preserving HMR, script
  scheduling budgets and per-entity permissions remain future tasks.
- Other non-FPS projects and subsystems must be separately audited for
  embedded gameplay decisions before claiming that **all** gameplay
  hardcoding is removed.

## Verification

- `node tests/gameplay_scripts_smoke.cjs` exercises movement, interaction,
  target movement, shooting, score, restart and pause using a mock engine.
- `python tools/generate_fps_arena.py --verify` checks the generated scene,
  script and skydome resources.
- `python -m unittest discover -s tests -p test_project_catalog.py`
  verifies script-first Project Manager templates.
- `python -m unittest discover -s tests -p test_game_dist.py`
  validates package integrity, script inclusion and V8 requirements.
- C++ syntax checks confirm Player/Editor source validity, but require the
  full CMake release build and actual provider test for production acceptance.
