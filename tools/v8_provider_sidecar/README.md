# Official V8 15.8.62 — NorthStarCpp developer sidecar

This integration uses the actual V8 15.8.62 JavaScript engine, downloaded from
Google's V8 build storage and executed as a separate d8.exe process. It
implements the existing NorthStarCpp engine.scripting ABI 2 through a native
scripting_v8_sidecar.dll with a synchronous framed IPC bridge.

DEVELOPMENT/TEST ONLY. This is NOT an approved public release provider.
d8 is a developer shell rather than a hardened embeddable SDK; hiding d8
globals in a Realm is NOT an adequate security boundary for untrusted JS.
Use trusted project scripts only. Do not bypass the production release gates.

## Rebuild, test and run

From the NorthStarCpp repository root in PowerShell:

    cmake -S tools/v8_provider_sidecar -B out/v8-official-windows/15.8.62/sidecar-build -G Ninja -DCMAKE_BUILD_TYPE=Release
    cmake --build out/v8-official-windows/15.8.62/sidecar-build --parallel 2
    python tools/v8_provider_sidecar/verify.py --e2e

Run the native first-person test using V8 as a separate child process:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\v8_provider_sidecar\launch.ps1 -Scene "Projects\NorthStar_FPS_Test\main.nscn" -Fps

For headless verification add -Warp -CheckScene.

## Verified

The engine's native scripting V8 smoke and script-service-override smoke pass.
Installed QA Player source-project and FAT/DB archive E2E both pass:
start -> four update frames -> engine.save markers -> stop -> exit 0.
The host DLL imports only KERNEL32.dll and msvcrt.dll. V8 and Qt native DLL
runtime families do not share the process.

## Remaining release conditions

The official Windows Stable V8 15.8 source branch and verified commit are
recorded in out/v8-official-windows/15.8.62/stable-source-pin.json.
The SDK preflight is in stable-sdk-preflight.json. The checked Windows machine
has 22.1 GiB free vs repository's 30 GiB full-build policy, lacks depot_tools
(fetch/gclient), GN, and a compatible Windows Clang/MSVC build toolchain.
The published d8 archive does not include V8 C++ headers/import libraries.

An embeddable SDK/provider, audited dependency ABI, signed security approval
and independent signed clean-Windows acceptance are still required for
build_dist.py production promotion. This developer module does not forge or
replace any of those attestations.


## Overlapped IPC and performance validation (2026-11-14)

The development provider uses Windows overlapped named pipes with a
deadline for both reads and writes, CancelIoEx, and an optional
northstar_v8_sidecar_cancel(context) function for concurrent cancellation.
Do not call cancel while destroying its context. Generic scripting ABI 2
remains synchronous; there is no task/future interface yet.

Unused contexts start no V8 process, while up to three reset idle workers
are cached for reuse. Multiple active contexts keep independent processes.

The exact engine-event source generated by ScriptRuntime::emit_event()
uses a cached function instead of recompiling JavaScript per frame.

Run native and Player E2E:

    python tools/v8_provider_sidecar/verify.py --e2e

Run 1,000,000-call soak including cancellation and memory checks:

    python tools/v8_provider_sidecar/stress.py --frames 1000000 --contexts 6

Run Player clamped-DT comparison using D3D11 WARP:

    python tools/v8_provider_sidecar/frame_benchmark.py

Full report: docs/V8_ASYNC_IPC_POOL_FRAME_PROFILING_2026-11-14.md.
